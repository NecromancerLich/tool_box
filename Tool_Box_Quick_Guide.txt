TOOL_BOX v1.0 - QUICK GUIDE
===========================
Authorized use only. Use Tool_Box only on systems, networks, services, accounts,
and data that you own or are explicitly authorized to test.

START
-----
bash ToolBox.sh

or:
chmod +x ToolBox.sh
./ToolBox.sh

On the first launch of each Tool_Box version, accept the authorized-use notice:
Accept terms and continue? [Y/n]:

EXTERNAL MODULES - HOW THEY WORK
--------------------------------
Location:
System & Configuration -> Settings -> External Modules

External modules add reviewed .txt-defined command pages without editing ToolBox.sh.
Loading a module definition does NOT execute its command.

A module may have up to three positioned option groups. v1.0 supports the reserved
structural markers <<OPTIONS>>, <<OPTIONS2>>, and <<OPTIONS3>>. The module menu
shows those groups separately while keeping continuous option numbering.

Module controls:
C = Custom Placeholder Values (module-local overrides)
A = Custom Arguments
X = Clear Customizations
R = Run
D = Module Help

This Quick Guide does NOT include module-creation instructions.
For full module-writing syntax, examples, category aliases, templates, validation,
and troubleshooting, see:
Tool_Box_External_Module_Guide.pdf

RECOMMENDED WORKFLOW
--------------------
1. Create/load a workspace.
2. Set target, subnet, ports, output directory, and defaults.
3. Use Dry-Run for unfamiliar commands/modules.
4. Run Nmap or a Scan Profile.
5. Import saved Nmap results into the workspace.
6. Review Service-Aware Recommendations.
7. Record Notes and Findings.
8. Use Results / Reporting to search output and generate a report.

SAFETY REMINDERS
----------------
- Confirm the target before R = Run.
- Confirm you are authorized.
- Review Command Preview.
- Use root only when needed.
- Do not hard-code real passwords/tokens/private keys into modules.
- Third-party programs may print or log sensitive information.
- Review saved output before publishing or committing it.
